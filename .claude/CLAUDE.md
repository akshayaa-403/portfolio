# Portfolio — Project Guide

Personal portfolio for **Akshayaa Kashyap** (Software Engineer, AI & data). Static, buildless site: plain HTML/CSS/vanilla JS, no framework, no package.json, deployable as static files.

## Reference docs (read these before design/style work)
- **[design-audit.md](design-audit.md)** — 2026-09-14 design critique. Start at §1 (priority fix order) and §2 (Part A, hand-verified findings with measurements). §3 is 101 unverified agent findings — reference only, and **read §5 Part D first**, it lists claims already proven wrong and the things that are fine. Supersedes this file's page map where they disagree (e.g. there is no experience section).
- **[color-scheme.md](color-scheme.md)** — full palette with hex codes and every CSS custom property. Written before the dark theme landed, so it documents the light theme only; `:root[data-theme='dark']` in [css/style.css](../css/style.css) is the source of truth for dark. There is no olive accent — the brand accent is the navy `#094e94`.
- **[redesign-metadata.md](redesign-metadata.md)** — stack, layout/sections, typography, design tokens, accessibility, assets, content locations, and known gaps/opportunities.

## Structure at a glance
- [index.html](../index.html) — single-page site: hero collage, skills strip, work, other work, hobbies, about, contact. **No experience section** — see design-audit A8.
- [project.html](../project.html) — dynamic project detail page (reads `?id=` query param).
- [hobby.html](../hobby.html) — dynamic gallery page (reads `?id=`).
- [work/](../work/), [hobbies/](../hobbies/) — **generated** share pages, one per project/gallery: real `<title>`/`og:` tags that redirect to the dynamic page. Never hand-edit; run `node tools/build-share-pages.js`, which also rewrites `sitemap.xml` and `js/hobby-dims.js`.
- [404.html](../404.html) — custom not-found page.
- [css/style.css](../css/style.css) — global styles + all design tokens (`:root`).
- [css/project.css](../css/project.css) — detail-page, hobby-page and 404 styles.
- [js/boot.js](../js/boot.js) — the only non-deferred script: applies the saved view mode + theme to `<html>` before first paint. Shared by every page; `theme.js`/`modes.js` must agree with its precedence rules.
- [js/util.js](../js/util.js) — shared `esc()`, `safeUrl()`, `onReady()`, `isEditing()`. Loaded first everywhere; everything else assumes it.
- [js/theme.js](../js/theme.js) — light/dark theme (`data-theme="dark"` on `<html>`), persisted to localStorage, OS preference honoured on first visit; plus the footer year. Exposes `window.portfolioTheme`.
- [js/modes.js](../js/modes.js) — graph/notebook/clean view-mode switcher (`data-mode` on `<html>`). `graph` was called `chaos` until the field landed; a stored `viewMode: 'chaos'` no longer matches the allow-list and falls back to the default, which is the right outcome, so there is no migration.
- [js/field.js](../js/field.js) — **the graph-mode hero**: an Obsidian-style force-directed graph of the whole site, on canvas. Every node is a real destination (4 section hubs, the 7 case studies, every tool in their stacks, the 3 galleries and every photograph in them, and the 4 off-site links) and every edge a real relationship; two projects sharing a tool are two hops apart, which is what forms the clusters. Hover lights a neighbourhood and dims the rest, clicking a node navigates, nodes can be dragged. Built from `projects` + `hobbies` at run time, so it cannot claim more than exists. Six categories, generated into the on-canvas legend from the same map that colours the dots: **Projects** and **Hobbies** lead (largest, darkest), then **Images**, **Tools**, **Sections**, **Elsewhere**. Only nodes that lead somewhere viewable navigate — `Tools` carry `nav: false`, exist purely so two projects sharing PyTorch sit near each other, and never show a pointer cursor. Every node drifts gently, and **the drift freezes while a node is hovered**: without that a 2px image dot wanders out from under the cursor between hover and click. Key details: distances are aspect-corrected; the layout **settles, then is scaled to fit the box, then settles again** so the lockup's keep-out ellipse reasserts (fitting alone put labels back over the CTA); labels are clamped by measured width so they cannot run off the canvas; tech nodes link to `#skills-h`. Must load **after** both data files — `onReady` fires synchronously for a deferred script, so `defer` alone is not enough. The canvas is `aria-hidden` and unfocusable on purpose: every node's destination is also a real focusable link further down the page, so the graph is never the only route to anything.
- [js/nav.js](../js/nav.js) — mobile menu, shared by every page.
- [js/hero-hover.js](../js/hero-hover.js) — prop hover-scale, the player's play/pause button, and the **hero lamp as the theme switch** (lit lamp = dark theme). Audio is **never** started by hover.
- [js/marquee.js](../js/marquee.js) — draggable skills marquee; also keeps the "Skills" heading aligned to the mode toggle.
- [js/squiggle.js](../js/squiggle.js) — animated `feTurbulence` underline; returns early under `prefers-reduced-motion`.
- [js/script.js](../js/script.js) — card rendering, scroll reveals, active-nav/header observers, draggable collage.
- [js/project-data.js](../js/project-data.js) — full copy for all 7 projects, including each one's `notes`, `tags` and repo dates (see conventions).
- [js/project-detail.js](../js/project-detail.js) — injects detail content + per-project meta. Renders the **marginalia** on Overview and The tricky part, and `alignNotes()` parks each note beside the phrase it annotates after layout.
- [js/tex.js](../js/tex.js) — hand-rolled TeX subset for the case-study formulas (no MathJax/KaTeX).
- [js/hobby-data.js](../js/hobby-data.js) — labels, blurbs, photo counts and captions for the 3 galleries. Read by `hobbies.js`, `hobby-page.js` **and** `tools/build-share-pages.js` — a bare global so the Node tools can evaluate it.
- [js/hobby-page.js](../js/hobby-page.js) also owns the gallery **popover**: every tile is a real `<button>` that opens a native `<dialog>` via `showModal()` (focus trapping, page inertness, Escape and `::backdrop` all come free — do not hand-roll an overlay). Deep-linkable as `hobby.html?id=<gallery>&i=<n>`, one-based; the graph's image nodes point straight at it, and stepping through images uses `replaceState` so twenty photographs do not bury the referring page under twenty history entries.
- [js/hobbies.js](../js/hobbies.js), [js/hobby-page.js](../js/hobby-page.js), [js/hobby-dims.js](../js/hobby-dims.js) — index tiles, gallery mosaic, and the generated image dimensions the mosaic sizes itself from.
- [js/layout-editor.js](../js/layout-editor.js), [js/annotate.js](../js/annotate.js) — dev-only, enabled with `?edit=1`. Hero props: **A** selects behind an overlapping prop, **D** dumps coordinates. A second editor at the end of layout-editor.js drags the bare phone cut-outs on the work cards; **P** dumps those as CSS. annotate.js is an alt-click comment layer; **C** copies the pins.
- [tools/check.js](../tools/check.js) — `node tools/check.js`, the only test there is: anchors, asset references, `rel="noreferrer"`, nav consistency, project data, that every margin note still quotes its paragraph exactly once (§8), and that the repo dates, tags and the graph's `#skills-h` target are well formed (§9). Run it after any markup change.
- [tools/build-share-pages.js](../tools/build-share-pages.js), [tools/build-image-variants.py](../tools/build-image-variants.py) — generators.
- [robots.txt](../robots.txt), [sitemap.xml](../sitemap.xml) — SEO (`sitemap.xml` is generated).

## Conventions to respect
- Keep it **static & buildless** unless explicitly asked to add tooling.
- The palette is **blue-on-paper**, sampled from `public/assets/favicon.png` (paper `#f4f7fa`, accent `#094e94`, deep `#00317a`), with a **dark theme** inverting the same navy family (`:root[data-theme='dark']`, ground `#0c1620`). Every new color must be a token in `:root` **and** get a dark counterpart. All text must meet WCAG AA in *both* themes — check against the notebook ground too, and remember notebook mode's hero text sits on a light photographic prop whatever the theme.
- Never hardcode a color that sits on `--accent-deep`: use `var(--on-accent-deep, #fff)`, which flips to dark navy when the accent goes pale in dark mode.
- Each project carries **`created` / `updated`** (ISO dates transcribed from the GitHub API's `created_at` / `pushed_at`, **not** fetched at run time — a live call would mean a third-party request per page view and a row that renders empty when the API is slow) and **`tags`** (`[[label, https url], ...]` — keywords pointing at the paper, spec or docs behind the idea). They render as the detail page's one horizontal header row: Date created · Last updated · Tech stack used · Tags. Arteza has no public repo, so it carries no dates and those two columns are simply omitted rather than filled with a dash. Re-fetch the dates with `curl -s https://api.github.com/repos/akshayaa-403/<repo>` when they go stale.
- Each project carries a `notes` object — `{ overview: [[phrase, note], ...], challenge: [...] }` — rendering as the **marginalia** on the detail page: the phrase is marked in the prose and the note is set in Caveat in the margin beside it, sides alternating. Each phrase must appear **exactly once** in the paragraph it annotates or the note is silently dropped; `tools/check.js` §8 catches that. The detail page is one centred column — year, role, stack and links live in the header, not a sidebar.
- Project case studies carry a `deepDive` array in [js/project-data.js](../js/project-data.js), rendered by [js/project-detail.js](../js/project-detail.js). Section kinds: `prose`, `figure`, `formula`, `code`, `table`, `steps`. Formulas are styled TeX source, **not** typeset — no MathJax/KaTeX, to keep the site buildless and offline-safe.
- Three **view modes** live on `data-mode`. **graph** (the default) replaces the stage with the latent field and hides every `.prop`, `.lily` and `.obj` in one rule; **notebook** is the hand-placed prop collage, and the only mode where the cards are draggable; **clean** hides every `.prop` and `.lily` outright. Do not reintroduce per-prop coordinates for graph or clean. New decorative elements must be hidden in both. Every mode pins `.hero__cta` with the rest of the lockup — left in normal flow it lands at the top of a full-stage lockup box and the sticky header clips it.
- The **notebook** hero is a **0px-exact copy of jackiehu.design's** above-the-fold layout (props carry `--x/--y/--w/--h` as % of a 1440x900 stage, with `object-fit: contain`). Verify with a live render before changing any coordinate — see redesign-metadata.md.
- The props in `public/assets/props/` are **borrowed third-party images** and must be replaced before publishing — see redesign-metadata.md.
- Preserve accessibility (skip-link, `:focus-visible`, `prefers-reduced-motion` gating, semantic landmarks).
- Keep the `js`-class + reduced-motion gating on any new animation, **and the 4s reveal failsafe** in script.js — without it, deep-anchor loads leave sections invisible.
- Project copy must match what the repos actually contain; several upstream READMEs overstate their stack (see redesign-metadata.md).
- Escape dynamic strings rendered via `innerHTML` (`esc()`/`safeUrl()` from [js/util.js](../js/util.js)).
- **Nothing on the site may start audio, or claim experience the page does not show.** A project with no real screenshot carries `"thumb": false` and renders a text-only card rather than shipping a placeholder image.
- Run `node tools/build-share-pages.js` after editing `js/project-data.js` or `js/hobby-data.js`, then `node tools/check.js`.
